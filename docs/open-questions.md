## Правила безопасности (локальная разработка)

- Изолированная директория, без доступа к личным файлам
- Без реальных Telegram/почта/Obsidian/аккаунтов
- Без полного доступа к ФС, браузеру, Windows GUI
- Без команд с административными правами
- Без фоновых сервисов и открытых портов
- Синтетические данные и тестовые директории
- Секреты/токены/документы — не в логи
- Опасные операции — после согласования

## Новые правила (v1.4)

- **LLM Gateway** (`16` §3.2): сторонние проекты → только через loopback Gateway с эфемерным ключом. Прямые ключи провайдера запрещены.
- **Adapter contract** (`16` §3.1): каждый сторонний проект оборачивается в адаптер, проходящий тест-набор соответствия (S7-T10).
- **Цепочка поставки навыков** (`16` §3.5): вендоринг в `skills/vendor/`, SHA-256, ревью SKILL.md, закрепление описаний MCP.
- **Визуальный канал** (`16` §3.4): скриншоты и HAR проходят проверку класса данных перед отправкой в VLM.
- **«Правило двух»** (`16` §2.2): GUI-агент (экран + приложения + действия) в режиме `open` запрещён без пошагового approval.
- **Статус `claimed`** (`16` §10): все внешние проекты считаются `claimed` до S0B-T5.
